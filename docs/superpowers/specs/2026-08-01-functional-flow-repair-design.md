# 功能流程修复设计

## 目标

逐项修复 phone 功能验证中发现的三个应用缺陷，并以 API 22 模拟器端真实操作证明流程可用：

1. 单位分类切换后根据现有输入立即重算。
2. ZIP 压缩选择器能显示并选择普通文件，完成压缩和保存。
3. `sample.wav` 能离线转换为 AAC 编码的 M4A 文件并保存。

不修改包名、应用 ID、签名、权限和离线安全边界。

## 根因

- 单位换算：分类点击仅重置索引并清空结果，没有调用已有 `calculate()`。
- ZIP 压缩：`DocumentSelectOptions.fileSuffixFilters` 收到 `['*']`，系统 FilePicker 不把它识别为任意文件过滤条件。
- 音频转换：`AVTranscoder` 的 API 22 定义面向视频转码，现有代码把纯 WAV 音频直接交给它，`prepare()` 返回 5400102 状态错误。

## 设计

### 单位换算

分类切换后重置来源和目标单位索引，然后调用 `calculate()`。空输入仍由现有逻辑清空结果，不增加新状态。

### ZIP 压缩

将压缩模式的通配符替换为项目已有的明确文件后缀集合。解压模式继续只允许 `.zip`。选择、临时目录复制、`zlib.compressFile()` 和系统保存流程保持不变。

### WAV 转 M4A

新增独立的原生 WAV 转码路径：

1. 解析 RIFF/WAVE 头，验证 PCM、采样率、声道数和位深。
2. 将 PCM 帧送入 API 22 `AudioEncoder`，编码为 AAC。
3. 使用 `AVMuxer` 写入 M4A/MP4 容器。
4. 监听编码完成和错误事件，确保输出关闭、编码器释放、文件描述符释放。
5. `AudioConvertService` 对 WAV→M4A 分派到该路径；其它输入不再错误宣称已支持，保持明确的失败提示。

首个验收范围为当前真实失败用例 `sample.wav -> sample.m4a`。不在本任务中引入 FFmpeg、网络依赖或扩展 MP3/FLAC/OGG 解码。

## 错误处理

- 非 RIFF/WAVE、非 PCM、损坏或不支持的 WAV 返回明确错误，不生成伪输出。
- 编码器或复用器错误原样保留错误码和阶段信息。
- 任一阶段失败都清理临时输出和句柄。
- 用户取消系统选择器或保存选择器保持现有行为。

## 测试

每项按 RED/GREEN 顺序执行：

1. 保留现有模拟器失败证据作为 RED。
2. 修改单项生产代码。
3. 运行标准静态检查和 ArkTS 构建。
4. 重新安装 HAP，在相同操作路径验证原始失败场景。
5. 保存操作前、动作、操作后截图或设备文件证据。

最终必须通过：温度即时重算、TXT 文件可选并压缩为 ZIP、WAV 转 M4A 并保存、既有文档/PDF/ZIP 解压回归、标准门禁和完整构建。
