# 万能格式转换 1.0 上架就绪设计

## 目标

本阶段交付一个能力诚实、可重复验证、满足提交审核前工程质量的 1.0 版本。成功标准是所有对用户启用和宣传的功能均有自动测试、HarmonyOS 构建及相称的设备闭环证据；未接入大型离线引擎的格式不作为 1.0 可用能力。

应用继续保持单机离线、无后端、无网络权限、数据不出设备。不得修改包名、应用 ID、签名身份或发布状态。

## 1.0 能力范围

### 对外启用

- 文本类文档：TXT、LOG、CSV、JSON、XML、HTML、Markdown 的现有可验证转换矩阵，以及文本/Markdown 导出 PDF。
- 图片：PNG、JPG/JPEG、WEBP、BMP 互转；尺寸调整、裁剪、颜色读取。
- 音频：16-bit PCM WAV 转 M4A；含 AAC 音轨的 MP4 无损提取 M4A。
- 视频：H.264/AAC MOV 无损重封装 MP4；设备原生编码器确实可用时的 MP4 转码路径。
- PDF：JPG/文本/HTML 生成 PDF；项目自产未压缩文本 PDF 导出 DOC/Markdown。
- 工具：ZIP 压缩/解压、时区换算、单位换算。

### 1.0 不宣称支持

- HEIF/GIF 编码和 MP3/AAC/FLAC/OGG 等通用音频转码。
- AVI、MKV、FLV、WMV 和非 H.264/AAC 视频的确定性通用转码。
- 压缩、加密、扫描或复杂字体 PDF 的反向转换与 OCR。
- DOCX、XLSX、PPTX 等二进制 Office 双向转换。

这些能力需要独立的离线 Native 引擎、许可证和包体评估，保留为后续版本。格式选择器可以保留禁用占位并统一显示“功能正在开发”，但不得进入文件选择、转换或保存路径，也不得在商店宣传文案中列为已支持能力。为降低审核中的完成度风险，不在首页增加无法使用的独立功能入口。

## 用户视角验证

每个启用流程记录三段证据：操作前状态、用户动作、操作后状态。覆盖：

- 首次启动、首页入口、返回导航和关于/隐私信息。
- 文件类型筛选、取消选择、空输入、重复文件和不匹配格式。
- 转换中禁用与进度、成功保存、保存取消、权限拒绝和转换错误。
- 输出文件扩展名、容器/文件头、尺寸、像素或文本内容的真实性。
- phone 与 2in1 布局；tablet 在缺少独立设备时明确标为外部证据缺口。
- 飞行模式/无网络权限下运行，不出现网络依赖或上传行为。

“全量通过”只适用于 1.0 启用矩阵，不扩张为任意格式均可转换。

## 开发者与上架视角验证

新增可重复执行的 release readiness 门禁，至少检查：

- `module.json5` 无 `ohos.permission.INTERNET`，无不必要权限。
- 应用/Ability 图标分辨率和资源有效性，启动图标不使用 48x48 占位图。
- `versionName`、页面版本文案和包元数据一致。
- 不包含示例域名、虚假邮箱、令牌、私钥或签名口令。
- 包名、应用 ID、签名配置只读审计；unsigned 产物不得标记为可上传包。
- debug 与 release 构建、Native ABI、混淆、HAP 包体和第三方许可证清单。
- 路由、资源、本地化、深色模式、无障碍语义和触控尺寸。
- 隐私声明与实际行为一致，外部隐私政策 URL、开发者主体和支持邮箱必须由发布者提供真实值。

## 实现设计

### 能力与文案收敛

以代码中的可执行矩阵为唯一事实源，对齐首页、格式选择器、README、设计文档和 QA。未支持格式在已有格式选择器中保留禁用状态，统一标注“功能正在开发”；占位状态不能被点击、不能进入执行白名单，且不计入 1.0 全量通过矩阵。

### 上架信息

用资源统一应用版本和用户可见文案，修复模块小图标资源。删除虚假的 `support@maxtools.com` 和 `https://maxtools.com/privacy`；在发布者尚未提供真实值前，界面只展示可证实的离线隐私说明，release readiness 门禁把真实支持邮箱、公开隐私政策 URL、发布签名列为外部阻塞。

### 门禁脚本

新增 `scripts/check-release-readiness.ps1`，输出 `passed`、`blocked`、`failed`：

- `failed`：代码或资源可修且不符合 1.0 设计，例如网络权限、占位域名、图标过小、能力文案失真。
- `blocked`：必须由发布者或平台提供，例如签名证书、真实隐私政策 URL、开发者主体材料。
- `passed`：静态、测试、release 构建和设备证据均满足要求。

脚本不得读取或输出证书口令、私钥内容或用户文件内容。

## 错误处理

- 不支持、损坏、加密和不匹配文件在生成输出前失败，错误提示说明具体边界。
- 失败时删除沙箱内不完整文件；保存取消不计为转换失败，也不显示成功。
- 批量转换逐文件记录结果，单个失败不应导致应用崩溃。
- 原生编码器或系统 picker 的设备限制与应用逻辑错误分别记录。

## 测试策略

所有代码修复先增加失败契约或算法测试，再实施最小修复。最终执行：

1. 全部 `scripts/test-*.js`。
2. `scripts/_type_check.js`。
3. `scripts/check-standard.ps1`。
4. `scripts/check-release-readiness.ps1`。
5. debug 与 release HarmonyOS 构建。
6. phone、2in1 代表性用户流程及真实产物校验。

设备证据保存至 `docs/qa/`，最终报告逐项区分 `passed`、`fixed`、`blocked` 和 `not in 1.0 scope`。

## 外部输入与阻塞

以下内容不能由代码代理伪造，也不在本阶段自动修改：

- 发布签名证书、Profile、私钥和口令。
- AppGallery Connect 中的开发者主体、应用 ID 和发布状态。
- 真实可联系的支持邮箱和可公开访问的隐私政策 URL。
- 商店标题、副标题、分类、关键词、截图和著作权材料的最终发布者确认。

代码完成不等于已可上传；只有外部材料齐备、release 签名包生成并通过平台预检查后，状态才能从“工程就绪”升级为“可提交审核”。
