# 离线转换能力扩展设计

## 目标

在不引入网络、后端或虚假格式输出的前提下，依次开发 BMP 图片输出、视频音频提取和 PDF 文本反向转换。每项能力只有在自动测试、HarmonyOS 构建和 phone 模拟器真实文件核验通过后才标记为可用。

## 实施顺序

1. BMP 图片输出。
2. MP4 提取音频为 M4A。
3. PDF 文本提取为 Word 兼容 DOC 和 Markdown。

顺序依据是实现风险和可验证性。BMP 可完全由 ArkTS 编码；M4A 可复用项目已有 AAC 编码与 MP4 封装经验；PDF 解析格式差异最大，最后单独收敛支持范围。

## BMP 图片输出

新增独立 `BmpEncoder`，输入 RGBA_8888 像素缓冲区、宽和高，输出标准 32 位未压缩 BMP。编码器写入 14 字节文件头、40 字节 DIB 头和 BGRA 像素数据，采用负高度表示自上而下存储，避免额外翻转整张图片。

`ImageConvertService` 继续负责解码和尺寸调整。当目标为 BMP 时读取 PixelMap 像素并调用 `BmpEncoder`；其他目标继续使用 ImagePacker。BMP 通过设备验证后重新标记为可用，HEIF 保持灰置。

验收要求：PNG→BMP 在模拟器成功保存；拉回文件以 `BM` 开头，可被 FFmpeg/Pillow 解码，尺寸为 320×200，关键像素与源图一致。

## 视频音频提取

页面将目标从虚假的 MP3 改为真实可实现的 M4A。服务层从 MP4 读取音频轨并生成 AAC 音频的 M4A 容器；不允许仅修改扩展名。若当前设备缺少所需解码器、编码器或封装能力，页面显示具体能力错误并清理临时文件。

视频转 MP4 与音频提取分开声明能力。当前模拟器缺少 AVC 视频编码器，因此 MOV→MP4 保持“设备能力受限”；这不阻塞 MP4→M4A 的独立验证。

验收要求：使用含 H.264 视频轨和 AAC 音频轨的 2 秒合成 MP4；输出必须为可解码 M4A，包含音频轨、不包含视频轨，时长约 2 秒。MP3 保持灰置。

## PDF 反向转换

新增独立 PDF 文本提取器，先支持项目自身生成的未压缩文本 PDF：

- ASCII literal string `Tj`。
- UTF-16BE 十六进制 `Tj`，包括项目生成器使用的 `FEFF` 前缀。
- PDF 字符串中的括号和反斜杠转义。
- 多页内容按页面顺序输出。

不宣称支持扫描件、加密 PDF、压缩对象流、嵌入子集字体或任意第三方复杂 PDF。检测到不支持结构或没有可提取文本时返回明确失败，不写入占位内容。DOC 输出继续使用 Word 兼容 HTML，Markdown 输出为提取出的纯文本。

验收要求：项目自产中英文 PDF 分别转换为 DOC 和 MD，拉回后文本一致；标准压缩 PDF 必须提示“当前解析器不支持”，不得报告成功或生成空文件。

## 架构边界

- 页面：文件选择、目标选择、进度、禁用和结果反馈。
- 服务：设备文件读取、转换编排、临时文件和保存流程。
- 转换器：BMP 二进制编码、PDF 文本解析等纯逻辑。
- 引擎：平台媒体能力与未来三方离线引擎的隔离边界。

新增代码不申请权限、不访问网络、不修改包名、签名或发布配置。

## 错误与资源处理

- 输入格式不匹配时在转换开始前拒绝。
- 平台编解码器不可用时显示设备能力提示。
- PDF 结构超出支持范围时显示解析限制。
- 所有打开的文件、PixelMap、ImageSource、ImagePacker 和媒体对象均在成功或失败路径释放。
- 失败时删除临时输出，不弹出保存成功提示。

## 测试策略

每项功能遵循测试先行：先添加最小失败契约或纯逻辑测试并观察预期失败，再实现最少代码使其通过。随后执行全部 Node 契约测试、标准静态检查、HarmonyOS 构建、安装和模拟器端到端验证。

QA 记录包含操作前状态、用户动作、操作后状态、截图、设备日志，以及拉回输出的文件头、尺寸、轨道、时长或文本内容。结论按“正常、已修复、受环境阻塞、当前未实现”分类。
