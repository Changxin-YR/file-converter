## 一、产品概述

### 1.1 产品定位

**万能格式转换**是一款本地单机文件格式转换工具,聚焦三大核心能力：

| 优先级 | 功能模块 | 能力说明 |
| --- | --- | --- |
| **主** | 文档格式转换 | 文本类格式互转（TXT / CSV / JSON / XML / HTML / Markdown）,PDF/Office 引擎扩展预留 |
| **主** | 图片格式转换 | PNG / JPG / JPEG / WEBP / BMP 互转与尺寸调整；HEIF 输出灰置 |
| **辅助** | 音频格式转换 | 16-bit PCM WAV → M4A |
| **辅助** | 视频与音轨 | H.264/AAC MOV → MP4 无损重封装；含 AAC 音轨的 MP4 → M4A |
| **辅助** | PDF 工具 | 正向生成 PDF；项目自产未压缩文本 PDF → DOC/Markdown |

所有转换均在设备本地完成,应用**不联网、无后端服务、不上传任何数据**。

### 1.2 目标用户

- 需要在不同平台间搬运文档/图片/音频的普通用户
- 有格式不兼容痛点（文档打不开、图片过大、音频播放器不识别）的用户
- 重视隐私、拒绝将文件上传第三方服务器的用户
- 需离线使用的场景（飞行模式、无网环境、涉密办公环境）

### 1.3 设计红线

以下为**不可违背的设计约束**：

| 编号 | 约束 | 说明 |
| --- | --- | --- |
| R1 | 单机离线 | 不申请网络权限,不发起网络请求 |
| R2 | 无后端 | 无服务端、无云存储、无账号体系 |
| R3 | 权限最小化 | 优先系统 picker 临时授权,按需动态申请 |
| R4 | 数据不出设备 | 不收集、不上传、不存储用户文件 |

## 五、图片格式转换

### 5.1 能力矩阵

基于 `@kit.ImageKit`（`image.createImageSource` / `image.createImagePacker`）。

**图例**：✅ 原生支持 | 🔶 需真机验证 | 🧩 三方引擎预留 | ❌ 不支持

| 源 \ 目标 | PNG | JPG/JPEG | WEBP | BMP | GIF | HEIF/HEIC |
| --- | --- | --- | --- | --- | --- | --- |
| PNG | - | ✅ | ✅ | ✅ | ❌ | ❌ |
| JPG/JPEG | ✅ | - | ✅ | ✅ | ❌ | ❌ |
| WEBP | ✅ | ✅ | - | ✅ | ❌ | ❌ |
| BMP | ✅ | ✅ | ✅ | - | ❌ | ❌ |
| GIF | ✅（首帧） | ✅（首帧） | ✅（首帧） | ✅（首帧） | - | ❌ |
| HEIF/HEIC | ✅ | ✅ | ✅ | ✅ | ❌ | - |

**要点**：
- BMP 输出由项目内 32-bit BI_RGB 编码器生成,不依赖 ImagePacker 的设备差异
- GIF 与 HEIF 编码当前不开放,UI 灰置
- RAW / SVG / ICO / PSD / TIFF 等非常用格式走 🧩 引擎扩展点
- 尺寸调整通过 `PixelMap.scale()` / `desiredSize` 实现

### 5.2 转换流程

```text
选择图片 → 解码(ImageSource) → PixelMap(RGBA_8888)
    → [可选] scale 缩放 → 编码(ImagePacker) → 写盘
```

### 5.3 核心实现（ImageConvertService）

```typescript
import { image } from '@kit.ImageKit'
import { fileIo as fs } from '@kit.CoreFileKit'
import { ConvertOptions, ConvertResult } from '../common/ConvertTask'

export class ImageConvertService {
  async convertFormat(
    sourcePath: string,
    targetPath: string,
    targetFormat: string,
    options?: ConvertOptions
  ): Promise<ConvertResult> {
    let imageSource: image.ImageSource | null = null
    let pixelMap: image.PixelMap | null = null
    let imagePacker: image.ImagePacker | null = null
    try {
      imageSource = image.createImageSource(sourcePath)
      const decodingOptions: image.DecodingOptions = {
        editable: true,
        desiredPixelFormat: image.PixelMapFormat.RGBA_8888
      }
      pixelMap = await imageSource.createPixelMap(decodingOptions)

      if (options?.width && options?.height) {
        const info = await imageSource.getImageInfo()
        let w = options.width
        let h = options.height
        if (options.keepAspectRatio ?? true) {
          const ratio = info.size.width / info.size.height
          if (w / h > ratio) { w = Math.round(h * ratio) }
          else { h = Math.round(w / ratio) }
        }
        await pixelMap.scale(w / info.size.width, h / info.size.height)
      }

      imagePacker = image.createImagePacker()
      const packingOptions: image.PackingOption = {
        format: this.getMimeType(targetFormat),
        quality: options?.quality ?? 90
      }
      const packedData = await imagePacker.packing(pixelMap, packingOptions)

      const file = fs.openSync(targetPath, fs.OpenMode.CREATE | fs.OpenMode.WRITE_ONLY)
      fs.writeSync(file.fd, packedData)
      fs.closeSync(file)

      return { success: true, targetPath }
    } catch (e) {
      return { success: false, errorMsg: (e as Error).message }
    } finally {
      pixelMap?.release()
      imageSource?.release()
      imagePacker?.release()
    }
  }

  private getMimeType(format: string): string {
    const map: Record<string, string> = {
      'png': 'image/png', 'jpg': 'image/jpeg', 'jpeg': 'image/jpeg',
      'webp': 'image/webp', 'bmp': 'image/bmp', 'heif': 'image/heif'
    }
    return map[format] ?? 'image/png'
  }
}
```

### 5.4 参数配置

| 参数 | 说明 | 默认值 |
| --- | --- | --- |
| quality | 输出质量（1-100） | 90 |
| width / height | 目标尺寸（px） | 原始尺寸 |
| keepAspectRatio | 保持宽高比 | true |

## 七、音频格式转换

### 7.1 能力矩阵

| 源格式 | 目标格式 | 状态 |
| --- | --- | --- |
| PCM WAV（format 1、16-bit、单/双声道） | M4A（AAC LC） | ✅ API 22 phone 模拟器已验证 |
| 含 AAC 音轨的 MP4 | M4A（无损重封装） | ✅ API 22 2in1 已完成选择、转换、保存与容器验证 |
| MP3 / AAC / M4A / FLAC / OGG | M4A | 🔶 尚未接入对应解码器 |
| 任意源 | MP3 / AAC / FLAC / WAV / OGG | 🔶 待离线引擎扩展 |

**API 22 关键约束**：`AVTranscoder` 在 PCM WAV 输入上会于 `prepare()` 阶段失败，因此确定性路径改为 Native C API。页面仍只启用 M4A 目标，服务对非 WAV→M4A 组合返回明确的不支持错误。

### 7.2 转换流程

```text
ArkTS 打开源/目标 fd
  → native_audio 解析 RIFF/WAVE fmt + data chunk
  → 同步 AudioCodec 将 PCM S16LE 编码为 AAC LC
  → AVMuxer 写入 M4A
  → Promise 回到 ArkTS，关闭 fd 并由用户通过系统保存器落盘
```

### 7.3 核心实现（AudioConvertService + native_audio）

- ArkTS：校验 WAV→M4A 组合，以 `READ_ONLY` / `READ_WRITE` 打开文件描述符，并在失败时删除不完整目标文件。
- C++：使用 `OH_MD_KEY_ENABLE_SYNC_MODE=1`，按 `Configure → Prepare → Start` 顺序启动 AAC 编码器，通过 `QueryInputBuffer` / `QueryOutputBuffer` 驱动数据流。
- MP4 音轨：`AVSource → AVDemuxer → AVMuxer(M4A)` 直接复制 AAC sample,不启动解码器或视频编码器。
- MOV 视频：H.264 视频轨与可选 AAC 音轨按 PTS 交错复制到 MP4，绕开设备 AVC 编码器；其他编码明确拒绝。
- 复用：从 `GetOutputDescription` 获取 AAC track format，调用 `OH_AVMuxer_AddTrack`、`Start` 和 `WriteSampleBuffer` 输出 M4A。
- 线程：NAPI 使用 `napi_create_async_work`，编码不阻塞 ArkUI 主线程。
- 资源：任一步骤失败均停止并销毁 codec/muxer、截断目标文件；ArkTS finally 关闭 fd。

### 7.4 参数配置

| 参数 | 说明 | 默认值 |
| --- | --- | --- |
| audioBitrate | 输出码率（bps） | 128000 |
| audioSampleRate | 当前不重采样，页面显示“跟随源文件” | 源文件采样率 |

常用预设：低质量 64kbps / 标准 128kbps / 高质量 256kbps / 无损 320kbps

## 八、转换引擎抽象层

### 8.1 设计目标

为覆盖尽可能多的格式,设计**引擎抽象层**,使转换逻辑与具体引擎解耦,可插拔、可扩展、可保持离线。

### 8.2 接口定义（IConvertEngine）

```typescript
export interface IConvertEngine {
  readonly engineName: string
  readonly nativelySupported: boolean

  supports(type: ConvertType, srcExt: string, dstExt: string): boolean
  convert(task: ConvertTask, onProgress: (percent: number) => void): Promise<ConvertResult>
}
```

### 8.3 引擎注册表（EngineRegistry）

```typescript
export class EngineRegistry {
  private engines: IConvertEngine[] = []

  register(engine: IConvertEngine): void {
    this.engines.push(engine)
  }

  resolve(type: ConvertType, srcExt: string, dstExt: string): IConvertEngine | undefined {
    for (const engine of this.engines) {
      if (engine.supports(type, srcExt, dstExt)) {
        return engine
      }
    }
    return undefined
  }
}
```

### 8.4 已注册引擎

| 引擎 | 基于 | 处理范围 |
| --- | --- | --- |
| NativeTextEngine | fileIo + util + DocumentMatrix | 文本类文档互转 |
| NativeImageEngine（服务内联） | @kit.ImageKit | 图片格式互转 |
| NativeMediaEngine（NAPI） | Native AudioCodec / AVSource / AVDemuxer / AVMuxer | PCM WAV 编码 M4A；MP4 AAC 音轨重封装 M4A；H.264/AAC MOV 重封装 MP4 |
| PdfTextExtractor | ArkTS 轻量解析 | 项目自产未压缩文本 PDF → 文本 |
| NapiEngine（预留） | 离线三方原生库 NAPI 桥接 | 复杂 PDF / Office 等 |

**约束**：任何三方引擎必须随应用打包、本地运行,严禁运行时下载。

## 十三、性能与稳定性

| 策略 | 说明 |
| --- | --- |
| TaskPool 多线程 | 图片/音频/大文档转换放入任务池,避免阻塞 UI |
| 内存管理 | PixelMap / ImageSource / AVTranscoder 在 finally 中 release |
| 大文件流式 | 超阈值文件流式读写,禁止一次性读入内存 |

| 失败兜底 | 不支持格式灰置,转换异常结构化展示,不崩溃 |

### TaskPool 用法示例

```typescript
import { taskpool } from '@kit.ArkTS'

@Concurrent
function convertImageTask(src: string, dst: string, fmt: string, quality: number): string {
  // 子线程执行,不访问 UI 状态
  return dst

const task = new taskpool.Task(convertImageTask, sourcePath, targetPath, format, quality)
const result = await taskpool.execute(task) as string
```
