# 测试报告合理建议修复设计

## 目标

依据 2026-08-03 测试报告核对当前代码，只修复能够由现有实现和 API 22 SDK 证明的问题：PDF 二进制输入边界、文档批量保存体验、Picker URI 文件大小读取兼容，以及音频跳过同格式文件时的进度与反馈。

应用继续保持单机离线、无后端、无网络权限和数据不出设备；不修改包名、应用 ID、版本、签名或 AGC 元数据。

## 核查结论与范围

### 纳入修改

- `PdfToolsPage` 将已打开 PDF 的实际字节直接传给 `PdfTextExtractor`，不再先用 UTF-8 文本解码。
- `PdfTextExtractor` 以 `ArrayBuffer` 为公开输入，使用逐字节映射保留 PDF 语法字节，再执行现有受限文本提取。
- 文档批量转换先在应用沙箱内逐个生成临时结果；全部可转换结果准备完成后，通过一次 `DocumentViewPicker.save()` 提交多个默认文件名，并将结果复制到返回 URI。
- 视频普通转码、MOV 重封装和 MP4 音轨提取均从已打开文件的 `fd` 调用 `statSync`，不再对 Picker URI 直接取文件状态。
- 音频遇到源格式等于目标格式时仍推进进度；完成反馈区分成功、跳过和失败，避免进度停留在非 100% 状态。

### 不纳入修改

- HEIF 已由共享 `FormatSelector` 按 `nativeSupported: false` 灰置、显示“功能正在开发”并阻止回调，报告建议已落实。
- 图片全部与目标格式相同时已有明确“无需转换”提示，且现有条件不会用该提示覆盖已记录错误。
- 音频采样率保持“跟随源文件”，因为当前 Native AudioCodec 路径没有重采样能力。
- 时区跨日计算未发现错误。
- PDF 反向转换仍只承诺项目自产未压缩文本 PDF；本轮修正输入表示方式，不扩展压缩流、加密、对象流、扫描件或复杂字体能力。
- 全量字符串国际化和颜色采样算法调整属于独立产品改造，不与本轮缺陷修复捆绑。

## 架构与数据流

### PDF 字节输入

`PdfToolsPage` 使用 `fs.openSync(uri)` 打开源文件，从 `fs.statSync(file.fd)` 获取长度，只把 `readSync` 实际读取的字节切片传给 `PdfTextExtractor.extract(buffer)`。提取器内部将每个字节映射为相同码值的字符，保证 `%PDF-`、对象字典、`BT/ET`、literal string 和十六进制 string 等 ASCII 语法不受 UTF-8 替换字符影响。

提取规则保持不变：检测到 `/Encrypt`、`/ObjStm`、`/Filter` 或没有可提取文本时明确失败，不创建输出文件。

### 文档批量保存

转换分为三个阶段：

1. 顺序读取并转换选中文档，将成功结果写入 `context.cacheDir` 下带任务标识的临时文件，同时记录默认文件名、临时路径和源序号。
2. 若至少有一个成功结果，调用 `SaveService.getSavePaths(fileNames)` 一次；`DocumentSaveOptions.newFileNames` 传入全部文件名，并校验返回 URI 数量与请求数量一致。
3. 顺序复制临时文件到对应 URI，更新成功数；无论保存成功、用户取消或复制失败，都在 `finally` 中清理本轮临时文件。

单个源文件读取或转换失败不会阻断后续文件。保存对话框取消视为整批未保存，保留明确状态但不继续弹窗。输出仍按源文件顺序与目标 URI 一一对应。

### 视频 Picker URI

三个视频入口遵循同一顺序：先 `openSync(sourceUri)`，再 `statSync(sourceFile.fd)`，最后把该 fd 和长度交给系统或 Native 转换能力。文件句柄继续在 `finally` 中关闭，失败产物继续清理。

### 音频跳过状态

每处理一个输入，无论转换、失败或因同格式跳过，都按输入索引更新总体进度。新增跳过计数用于最终状态：有成功结果时同时报告成功数与跳过数；全部跳过时显示无需转换；有失败且没有成功时保留具体失败信息。

## 错误处理与资源管理

- PDF、文档和视频均只使用已打开 fd 获取大小，避免 Picker URI 路径语义差异。
- 文档临时文件名包含任务 ID，避免同名源文件互相覆盖。
- 文档批量目标数量不匹配时停止复制并报告错误，不进行不确定映射。
- 文档临时文件在统一 `finally` 中清理；原有 PDF、视频和音频句柄释放规则不削弱。
- 用户取消系统保存对话框不会被报告为转换成功。

## 测试与验证

- 扩展 PDF 提取器测试：先以字符串专用 API 约束复现失败，再验证包含非 UTF-8 字节的 `ArrayBuffer` 仍能提取项目文本 PDF，并继续拒绝压缩、加密、对象流和空文本 PDF。
- 新增文档批量保存契约：先验证当前逐文件调用失败，再约束 `SaveService.getSavePaths()`、单次批量保存、沙箱暂存和统一清理。
- 扩展视频能力契约：先验证三个入口仍对 URI 调用 `statSync`，再约束全部使用已打开 fd。
- 扩展音频能力契约：先复现同格式跳过不推进进度，再约束跳过计数与进度更新。
- 执行全部 `scripts/test-*.js`、ArkTS 类型检查、`scripts/check-standard.ps1` 和 `scripts/build-harmony.ps1`。
- 若当前 phone/2in1 设备端点可用，执行操作前状态、用户动作和操作后状态的代表性交互回归；不可用时在 QA 中如实标记 `blocked`，不以静态检查替代设备证据。
