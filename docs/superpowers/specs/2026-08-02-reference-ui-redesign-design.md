# 万能格式转换参考图 UI 重构设计

## 目标

以用户提供的八屏参考图为唯一主视觉基准，重做全部 ArkUI 页面。在 phone 参考宽度下还原页面层级、比例、间距、颜色、卡片、按钮、胶囊、图标和插画；未提供的页面沿用同一设计语言。业务服务、转换引擎、离线边界和真实能力矩阵不改变。

“还原”指应用内容区的视觉和交互还原，不伪造系统状态栏、系统文件选择器或系统保存弹窗。phone、tablet、2in1 使用同一设计系统，并按设备宽度响应式排版。

## 产品边界

- 已开发能力保持可操作，并保留现有文件选择、转换、保存、进度、成功和错误流程。
- 未开发能力保留参考图中的位置、尺寸和标签，但使用灰色禁用态，不响应点击，不进入选择、转换或保存路径。
- 参考图中与真实能力冲突的宣传文案必须改为诚实文案。例如 Word/Excel、MP3/WAV/AAC、7Z/TAR.GZ/RAR 不标记为可用。
- 应用继续单机离线，不新增网络权限、后端、统计或用户文件持久化。

## 视觉方向

整体为轻盈、精密的蓝白工具界面：冷白背景，少量雾蓝层次，深色标题，高纯度蓝色强调，半透明浅蓝胶囊，细描边卡片和克制阴影。蓝色渐变仅用于主操作按钮与少量选中态，避免整页单色化。

### 基础令牌

| 类型 | 设计值 |

## 视觉资源

建立一致的蓝白 3D 资源组，包括首页主插画、八个工具图标、图片/文档选择插画、PDF 工具图标、归档与单位图标。资源使用透明背景 PNG，按 2x/3x 密度输出；不得继续使用 emoji 作为主要界面图标。

资源风格统一为半透明白色材质、蓝色边缘光、柔和投影和轻微等距视角。首页主插画保留参考图中的文件卡片与环形轨道意象；PDF、图片、归档等页面使用对应对象，不使用无关装饰。

## 共享组件

新增或重构以下复用组件：

- `AppPageHeader`：返回按钮、页面标题和可选历史图标。
- `PrimaryActionButton`：蓝色渐变、禁用灰蓝、加载状态和固定高度。
- `FilePickerPanel`：插画、标题、支持说明、选择按钮和已选择状态。
- `SegmentedControl`：档案/时区、图片调整/裁剪/颜色三段切换。
- `OptionChipGroup`：目标格式、编码、时区和单位选择；支持选中、默认和开发中状态。
- `ToolListItem`：PDF 工具列表图标、标题、说明和箭头。
- `MetricInputField`：带单位或字段标签的输入框。
- `StatusPanel`：进度、成功、失败和批量结果反馈。
- `FunctionTile`：首页图标、标题、说明和禁用状态。

共享组件只负责视觉和基础交互，页面仍负责组合；转换规则留在服务与引擎层。

## 页面设计

### 首页

- 顶部区域高度约 `154vp`，左侧显示品牌标题、副标题，右上保留皇冠标识，中部放置文件转换主插画。
- 主体为 2 列 4 行工具网格，卡片高度约 `74vp`，图标在左、标题和两行以内说明在右。
- 底部导航固定为首页/关于，选中项为蓝色图标与文字，背景为白色并带顶部细描边。
- 2in1 将网格扩展为 4 列 2 行，主插画与标题保持视觉中心。

### 图片、文档、音频与视频转换

- 顶部使用统一标题栏。
- 第一块为大尺寸 `FilePickerPanel`，左侧插画，右侧标题、支持说明和选择按钮。
- 下方依次为目标格式胶囊、参数控件、辅助说明和主按钮。
- 图片保留质量滑杆；文档保留源编码；音频保留码率；视频保留 MP4/M4A 路径说明。
- 未支持格式显示相同胶囊轮廓，但背景、文字和图标均灰化，并附小号“功能正在开发”。

### PDF 工具箱

- 顶部右侧使用 PDF 文件夹插画。
- 工具入口使用单个白色列表容器，行间细分隔线；每行包含彩色图标、标题、说明和右箭头。
- 已支持工具进入现有详情流程；未支持工具灰置且无箭头强调，不响应点击。

### 档案与时间

- 顶部双段控件切换档案转换和时区转换。
- 档案页使用压缩/解压小型胶囊、虚线文件选择面板、格式状态列表和底部主按钮。
- ZIP 显示绿色“可用”；7Z、TAR.GZ、RAR 显示灰色“功能正在开发”。
- 时区页使用小时/分钟输入框与两组时区胶囊，底部可使用低对比地球插画，但不得遮挡结果。

### 单位换算器

- 顶部为图标分类网格，覆盖重量、长度、面积、体积、温度、速度、时间和数据存储。
- 中部为无边框浅灰输入框，下方分别显示“从”和“转换为”单位胶囊。
- 换算结果位于输入区下方，字体层级明确，不依赖颜色表示成功。

### 图片工具

- 顶部三段控件切换图片调整、裁剪图片和颜色选择器。
- 统一使用虚线图片选择区。
- 调整页面使用宽高输入和比例开关；裁剪页面使用宽、高、X、Y 四字段；颜色页显示取色区域和十六进制/RGB 结果。
- 主按钮始终位于内容末端，未选择图片时灰化。

### 关于、结果与错误状态

- 关于页沿用首页顶部品牌语言，展示可证实的离线隐私、版本和本地处理说明，不展示虚假邮箱或 URL。
- 成功结果使用绿色状态图标、输出名称和保存按钮；失败使用红色状态文字和可理解原因。
- 文件选择取消保持原状态，不显示错误；处理中禁用会改变任务参数的控件。

## 响应式规则

- phone：以参考图为精确基准，单列内容、2 列首页网格、固定底部导航。
- tablet：内容最大宽度 `840vp` 居中，首页 4 列，转换页可将选择卡与参数区分成两列。
- 2in1：保持 `NavigationMode.Stack`，窗口较窄时回退 phone 结构，宽窗口使用双列；不可再次出现自动分栏窄侧栏。
- 页面使用安全区和滚动容器，软键盘出现时主按钮和输入框不得互相遮挡。

## 实现边界

- 业务服务、转换器、Native 模块和能力矩阵原则上不改。
- 页面只迁移布局与状态绑定，不在 `@Builder` 内做临时计算。
- 颜色、间距、尺寸和阴影集中到资源与共享常量。
- 路由、文件选择和保存流程沿用现有实现。

## 验收标准

1. phone 八个参考页面逐页截图，与参考图核对层级、间距、尺寸、圆角、颜色、图标和文字溢出。
2. 音频、视频、关于和所有结果/错误状态符合相同设计系统。
3. 未开发功能保持参考布局但完整灰化，无法触发执行路径。
4. phone 与 2in1 不出现内容重叠、窄侧栏、裁切或不可点击控件；tablet 缺设备时明确记录证据缺口。
5. 所有已有自动测试、ArkTS 类型检查、静态门禁和 HarmonyOS 构建通过。
6. 已开发转换功能完成代表性设备回归，确保视觉重构未破坏文件选择、转换和保存。
